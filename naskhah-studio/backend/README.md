# Backend Services

Naskhah Studio uses Supabase Auth, PostgreSQL/RLS and Supabase Edge Functions.

## Verified frontend routes
- Supabase project URL is configured in `app.js`.
- General auth/admin route: `/functions/v1/naskhah-v1-auth`
- Legacy login/admin route: `/functions/v1/naskhah-login`
- Secure user login route: `/functions/v1/naskhah-secure-login`

## Secure Login & User Provisioning
The secure user-login flow uses email + password and Cloudflare Turnstile. The public Turnstile Site Key is rendered in the browser. The Turnstile Secret Key is stored only as the Supabase Edge Function secret `TURNSTILE_SECRET_KEY` and is never committed to this repository.

Admin-provisioned accounts use a temporary password chosen or generated by the admin. New accounts and admin password resets set `nv1_profiles.must_change_password = true`. The user must change that password before application access. The current user password is never stored in `nv1_profiles`, admin audit details, or frontend persistence.

The live Supabase project has the additive `must_change_password boolean not null default false` column applied to `nv1_profiles`. Existing users default to `false`; newly provisioned/reset users are marked by the auth Edge Function.

## Edge Function source status
The production Edge Functions are managed in Supabase. This frontend repository documents verified routes and behavior but does not contain any secret values. If function source is brought into this repository later, use a Supabase CLI project layout and keep secrets in Supabase/Vercel environment configuration only.

## PHP
There is no PHP backend in the current application. Do not place PHP files here unless PHP is intentionally introduced as a future architecture change.
